# Explicit Keep and return

**Status:** bounded opt-in Keep behavior was demonstrated in the emulator. Keep
remains off by default while additional failure cases are qualified.

## Scope and implementation

**New kept** creates a tmux-backed terminal with a platform notification and explicit
Stop. It does not adopt or replace an already-running plain shell/editor. Plain work
remains Console-bound.

Keep consent, Android user/CE authority, foreground/unlocked terminal access and
presentation continuity are separate requirements. Native operations retain actual
Binder UID/SID/object-lifetime and epoch checks, existing resource bounds and the
worker syscall filter.

- Grant before computation: establish the exact notification and platform epoch
  before starting kept work. Pending Stop/death must defeat a late grant.
- Return through a fresh client/PTY, presentation ID, journal and parser. Do not rebase
  discarded output or infer a screen from an acknowledged tail.
- Notification Stop targets the old process-bound `IKeptWork` Binder, not a delayed
  reusable service name. Init performs whole-group cleanup; a request is not an ack.
- Keep adds no wake lock, external listener or automatic work restart after reboot.

## Observed opt-in Keep result

The emulator checks exercised unsaved editor return after Console-process loss,
relock, native programming, notification Stop with Console absent, detached End,
ordinary-app isolation and reboot without automatic Keep. An actual Android watchdog
platform-process failure ended kept work; fresh explicit work succeeded afterward.

The [notification follow-up](2026-09-14-keep-failure-controls.md) adds owner channel
blocking and locked Stop under the owner's notification-visibility settings.

## Verification limits

The platform-death result is not independent key withdrawal or a deliberately delayed
snapshot reply. Busy-key behavior, backend failure, pressure/suspend and supported-phone
behavior need their own controls. A subsequent UI-driver audit rejected one stale
readiness observation; a separate fresh observation preceded the relevant input.
The [reusable freshness guard](../scripts/proof/ui_queue.md) prevents that fixture error.
